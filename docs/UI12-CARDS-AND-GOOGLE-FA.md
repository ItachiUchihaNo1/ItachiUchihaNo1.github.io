# راهنمای رفع خطای ورود گوگل در مرشد

خطای `Error 400: redirect_uri_mismatch` یعنی آدرس بازگشت ارسالی سایت با آدرس مجاز همان کلاینت در گوگل یکسان نیست.

1. https://console.cloud.google.com/auth/clients را باز کنید و پروژه‌ای را انتخاب کنید که Client ID مرشد را در آن ساخته‌اید.
2. در **Google Auth Platform → Clients** روی نام کلاینت با نوع **Web application** بزنید. اگر کلاینت از نوع Android یا Desktop است، کلاینت Web بسازید.
3. پایین تنظیمات، در **Authorized redirect URIs** دکمهٔ **Add URI** را بزنید و عین این مقدار را وارد کنید:

```
https://morshedapp.ir/index.php?r=%2Fauth%2Fgoogle%2Fcallback
```

4. **Save** کنید. این مقدار را در JavaScript origins نگذارید. در صورت نیاز Origin سایت فقط `https://morshedapp.ir` است.
5. در فایل خصوصی هاست `morshed-core/config/local.php` بخش `google` را بررسی کنید:

```php
'google' => [
    'enabled' => true,
    'live_verified' => true,
    'client_id' => 'CLIENT_ID.apps.googleusercontent.com',
    'client_secret' => 'SECRET_FROM_THE_SAME_WEB_CLIENT',
    'redirect_uri' => 'https://morshedapp.ir/index.php?r=%2Fauth%2Fgoogle%2Fcallback',
],
```

این نمونه را با تنظیمات موجود ادغام کنید؛ کل فایل را جایگزین نکنید. Client ID و Secret باید متعلق به همان کلاینت وب باشند. Client ID با https شروع نمی‌شود. هیچ‌کدام از مقادیر محرمانه را در گیت‌هاب، چت یا اسکرین‌شات منتشر نکنید.

6. ورود را از مرورگر معمولی باز کنید و روی «ورود با گوگل» بزنید. اگر هنوز خطای mismatch بود، در صفحهٔ خطای گوگل **error details** را باز کنید؛ مقدار `redirect_uri` باید دقیقاً با مقدار ذخیره‌شده در مرحلهٔ ۳ یکسان باشد. تفاوت www، http/https، اسلش انتهایی، حروف و کدگذاری %2F هم مهم است.
7. اگر برنامه در حالت Testing است، حسابی که با آن تست می‌کنید را در **Audience → Test users → Add users** اضافه کنید. این مرحله مربوط به خطاهای محدودیت آزمایش است، نه رفع mismatch.

منبع رسمی: https://developers.google.com/identity/protocols/oauth2/web-server#authorization-errors-redirect-uri-mismatch

## کارت‌ها و پسندها در نسخهٔ UI12

- شهر از مشخصات ثبت‌شدهٔ مرشد، تگ مسئله از طبقه‌بندی فعالِ نسخه‌های منتشرشده، تعداد تجربه از تجربه‌های منتشرشده و تعداد گفت‌وگو از رزروهای پایان‌یافته خوانده می‌شود. عددهای نمایشی ساختگی نیستند.
- پسندها متعلق به حساب هستند و در دستگاه‌های دیگر پس از ورود هم در «حساب → مرشدهای پسندیده» دیده می‌شوند.
- شمارندهٔ بازدید از انتشار این قابلیت آغاز می‌شود. بازکردن دوبارهٔ همان تجربه در همان نشست تا ۳۰ دقیقه دوباره شمرده نمی‌شود؛ این شمارنده تعداد افراد یکتا یا آمار تاریخی نیست.
- در اولین استفاده، فقط دو جدول افزایشی `m_saved_mentors` و `m_experience_metrics` ساخته می‌شوند؛ داده‌های حساب، ورود، تجربه و تنظیمات قبلی تغییر نمی‌کنند و اجرای دستی SQL لازم نیست. حساب دیتابیس باید مانند نصب اولیه مجوز CREATE TABLE داشته باشد.
- هیچ بازدیدکننده‌ای نمی‌تواند پسندهای حساب دیگر را بخواند یا تغییر بدهد. ذخیره فقط پس از ورود و با تأیید CSRF انجام می‌شود.
