# نتایج آزمون بسته اجرایی

تاریخ تحویل: ۲۰۲۶/۱۰/۱۷. محیط محلی: PHP 8.4.26 و MariaDB 10.11.14، سرورهای HTTP واقعی روی loopback، دیتابیس تصادفی جدا و بدون ارسال بیرونی.

| مجموعه | نتیجه |
|---|---:|
| هویت، رمز/OTP، نشست و مدیریت | ۴۰ موفق |
| محتوا، مرشد، تقویم، رزرو، متن، نظارت و سازمان | ۵۸ موفق |
| هویت خارجی با RSA/HMAC و HTTP مصنوعی فقط در tests | ۲۴ موفق |
| اعلان، تنظیمات و اعتبارسنجی فایل | ۱۱ موفق |
| HTTP واقعی، سه رقابت پردازشی، آپلود/دریافت، نصب و بازیابی | ۳۳ موفق |
| اجرای migrationها روی DB خالی | ۱ موفق |
| JavaScript حفظ پیام/ACK در خطای شبکه و ذخیره | ۴ موفق |
| تولید کلید آفلاین | ۲ موفق |
| مجموع بررسی‌های بالا | **۱۷۳ موفق، صفر ناموفق** |

۸۵ فایل PHP از نظر syntax بررسی شدند؛ JavaScriptهای تحویلی و Python آزمون/بسته‌بندی نیز بررسی می‌شوند. خروجی خام آزمون‌های PHP/HTTP در TEST-OUTPUT.txt است. نام رمزها و حساب‌های tests صرفاً fixtureهای محلی‌اند و به SQL نصب منتقل نمی‌شوند.

## آزمون‌های معنادار

- دو فرآیند مستقل برای اولین مدیر، مصرف یک OTP و تصاحب یک ظرفیت اجرا شدند؛ فقط یک عملیات مجاز موفق شد.
- ویرایش، درخواست اصلاح و رد تجربه، نسخه عمومی قبلی را حفظ می‌کنند. تأیید جدید اشاره‌گر را جابه‌جا می‌کند؛ محتوای غیرفعال از ویترین دستی نیز حذف می‌شود.
- ظرفیت، فاصله، تعطیلی، مهلت رزرو، توقف پذیرش و عضویت سازمان مشترک در سرور بررسی شدند. پیشنهاد زمان با رزرو رقیب تعارض پیدا کرد و زمان قطعی قبلی باقی ماند.
- خطای واقعی DB با trigger کنترل‌شده هنگام ذخیره پیام ایجاد شد؛ هیچ پیام یا ACK ناقص باقی نماند. فرم HTML متن را حفظ کرد و retry HTTP فقط یک شناسه پایدار گرفت. JavaScript نیز شبکه قطع، رد ذخیره و ACK نامنطبق را موفقیت تلقی نکرد.
- بارگذاری واقعی multipart، نگهداری فایل خارج وب، checksum و دریافت مجاز بررسی شدند. صاحب‌نبودن و نقش مدیر بدون grant مانع دریافت شد.
- مستند تجربه پیش از انتشار قابل دریافت عمومی نبود، با نسخه تأییدشده منتشر و با توقف انتشار بسته شد. عکس مرشد پس از تغییر دوباره نیازمند بررسی شد.
- مدیر سامانه بدون مجوز آرشیو نتوانست متن را بخواند. grant برای ناظر مشخص، انقضا، لغو، استقلال تأیید و مالکیت شکایت بررسی شد.
- dump واقعی محلی گرفته و تمام ردیف‌های تمام جدول‌ها پس از restore مقایسه شدند؛ سپس نشست، OTP و state snapshot باطل شدند. SQL یکپارچه نصب تازه نیز روی DB خالی دیگر import شد.
- رابط دسکتاپ، جست‌وجو، ورود مدیریت و افزودن/انتخاب بلوک ویترین در مرورگر دیده شدند. تصویر UI-ADMIN.png داده آزمایشی را نشان می‌دهد، نه محتوای نصب اولیه.

## مواردی که این نتیجه اثبات نمی‌کند

اجرای روی MySQL 8.0.46/cPanel کاربر، SSL و Secure cookie واقعی، ارسال TSMS و دریافت موبایل، رفت‌وبرگشت گوگل و SDK/تأیید زنده ایتا، پیام اعلان بیرونی، موبایل واقعی/مرورگر داخلی ایتا، دسترس‌پذیری جامع، تست بار/نفوذ مستقل و سرویس رسانه صوت/تصویر/ضبط آزمون نشده‌اند. آزمون ضبط در زیرساخت رسانه انجام نشده و با آزمون ذخیره متن جایگزین نمی‌شود.

## تکرار توسعه

`tests/run_local.py` به مسیر PHP دارای pdo_mysql/cURL/OpenSSL/fileinfo، سرور MySQL/MariaDB موقت با data directory آماده و پوشه work نیاز دارد. دیتابیس تصادفی localhost ایجاد و سرورها پس از آزمون متوقف می‌شوند. با وجود mariadb-dump کنار سرور، backup/restore نیز آزمون می‌شود. این ابزار برای cPanel نیست و رمز یا DB تولید به آن داده نشود. Node فقط برای tests/durable_message.cjs و tests/offline_keys.cjs لازم است.

## اصلاح عیب‌یابی نصب

پس از گزارش خطای نصب، ثبت خطا به کدهای مجاز بدون متن خام exception اصلاح شد. ۲۲ سناریوی هدفمند شامل خطای قالب config، app_key/environment، نسخه schema، PDO و نشست موفق بودند؛ هیچ رمز، مسیر یا نام کاربری exception در خروجی طبقه‌بندی نیست. آزمون کامل ۱۷۳ مورد بالا مربوط به بسته پایه است و پس از این اصلاح دوباره اجرا نشده؛ آزمون هدفمند اصلاح و syntax اجرا شده‌اند. فایل آزمون جدید installation_diagnostics.php است.
