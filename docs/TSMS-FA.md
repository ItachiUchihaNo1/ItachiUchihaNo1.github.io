# اتصال TSMS در هسته حساب

سرویس `Identity/Accounts` کد شش‌رقمی تصادفی تولید می‌کند، HMAC وابسته به شناسه challenge را در DB می‌گذارد و خود کد را فقط به قرارداد `SmsGateway` می‌دهد. هیچ کد خام در DB، اعلان یا حسابرسی ذخیره نمی‌شود. درگاه کنونی `TsmsSendOnlyGateway` فقط ارسال کد ورود دارد؛ دریافت SMS، XML و ارسال انبوه وارد برنامه نشده‌اند.

تنظیمات در `morshed-core/config/local.php` خصوصی و بخش sms هستند: username/password/sender، enabled، https_post_confirmed، environment و allowed_recipients. در staging پس از باز شدن هر دو قفل، فقط شماره‌های استاندارد `09...` داخل allowlist ارسال می‌گیرند. خود خط ارسال، نام کاربری، رمز یا شناسه الگو حدس زده نشده‌اند. اگر ارائه‌دهنده قرارداد جدید یا الگو بخواهد، مستندات همان حساب باید مبنا قرار گیرد.

نمونه پایتون کاربر HTTP و GET با اسرار در URL داشت. آداپتور از HTTPS POST به مسیر ثابت `https://tsms.ir/url/tsmshttp.php` با پارامترهای from/to/username/password/message استفاده می‌کند؛ TLS اعتبارسنجی و redirect مسدود است. **پشتیبانی واقعی POST با اعتبارنامه معتبر هنوز تأیید نشده**؛ انتقال ناموفق به GET/HTTP fallback ندارد. آزمون GET و POST خالی بدون اعتبارنامه در مرحله قبل پاسخ 200 با متن `4` داد؛ این فقط پاسخ endpoint را نشان می‌دهد و آزمون ارسال نیست.

پاسخ ناشناخته یا هر عددی به‌عنوان موفقیت فرض نمی‌شود. چون نمونه پایتون قالب پاسخ موفق را مشخص نکرده، پارسر موفقیت تأییدشده هنوز نصب نشده است. وضعیت unverified_response یا submission_uncertain به معنی تحویل نیست؛ اگر پیامک واقعاً به مالک رسید، فقط ورود کد صحیح در مهلت و با محدودیت تلاش، مالکیت شماره را ثابت می‌کند. در وضعیت disabled/provider_rejected، challenge قابل مصرف نیست و API ارسال کد 503 می‌دهد. در timeout، retry خودکار نداریم چون پیامک ممکن است قبلاً ارسال شده باشد.

قبل از فعال‌سازی واقعی باید قرارداد امن ارائه‌دهنده، خط خدماتی، پاسخ موفق و خطاها، شماره آزمایش تحت کنترل، شماره بلک‌لیست، timeout، سقف هزینه و اتصال خروجی HTTPS از خود هاست بررسی شوند. اسرار فقط روی سرور خصوصی وارد شوند؛ آن‌ها را در چت ارسال نکنید. مسیر عمومی ارسال آزاد پیامک وجود ندارد؛ API به CSRF، rate limit و challenge سروری وابسته است.

در این نسخه هیچ پیامک واقعی ارسال نشده است. آزمون با `TestSms` فقط در CLI داخل tests انجام می‌شود و هیچ test-mode login یا راه خواندن کد برای کاربران وب ارائه نشده است.

منبع عمومی رسمی: [TSMS — URL برنامه‌نویسی](https://www.tsms.ir/posts/dll-%D9%88-url-%D9%87%D8%A7%DB%8C-%D9%88%DB%8C%DA%98%D9%87-%D8%A8%D8%B1%D9%86%D8%A7%D9%85%D9%87-%D9%86%D9%88%DB%8C%D8%B3%DB%8C). پارامترها و کدهای خطا در این نسخه از فایل پایتون ارائه‌شده استخراج شده‌اند و قرارداد نهایی ارائه‌دهنده محسوب نمی‌شوند.
