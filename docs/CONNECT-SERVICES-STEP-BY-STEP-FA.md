# راهنمای اتصال پیامک، گوگل و ایتا

این راهنما برای مدیر هاست است. اطلاعات محرمانه را در گیت‌هاب، گفت‌وگو، تصویر یا Document Root قرار ندهید.

## فایل درست کدام است؟

در File Manager وارد `morshed-core/config/local.php` شوید. ابتدا از همین فایل در یک محل خصوصی پشتیبان بگیرید. فایل `local.example.php` فقط نمونه است و برنامه آن را نمی‌خواند. سه بخش `sms`، `google` و `eitaa` را در آرایهٔ موجود ویرایش کنید؛ بخش تکراری نسازید، `return` جدید اضافه نکنید و `app_key`، دیتابیس و تنظیمات نصب را عوض نکنید. کل فایل نمونه را روی تنظیمات فعلی کپی نکنید.

## ۱. پیامک TSMS: فقط ارسال

کد PHP فقط کد ورود را می‌فرستد؛ دریافت پیامک، اعتبارخوانی و صندوق پیامک پیاده یا فعال نشده‌اند. روش GET کد پایتون به cURL سمت سرور تبدیل شده، با HTTPS و تأیید گواهی، بدون انتقال به HTTP و بدون ثبت URL حاوی رمز. POST نیز برای نصب‌هایی که پشتیبانی آن را تأیید کرده‌اند حفظ شده است.

برای اولین آزمون کنترل‌شده، این بخش را در `local.php` تنظیم کنید؛ مقادیر بزرگ‌نویسی‌شده باید با اطلاعات واقعی پنل خودتان جایگزین شوند:

```php
'sms' => [
    'enabled' => true,
    'https_transport_confirmed' => true,
    'method' => 'GET',
    'environment' => 'staging',
    'allowed_recipients' => ['YOUR_TEST_MOBILE'],
    'username' => 'YOUR_TSMS_USERNAME',
    'password' => 'YOUR_TSMS_PASSWORD',
    'sender' => 'YOUR_TSMS_SENDER_LINE',
],
```

شماره آزمایش باید به شکل `09xxxxxxxxx` باشد. `sender` همان خط ارسال خریداری‌شده است، نه شماره همراه شما. کلید قدیمی `https_post_confirmed` لازم نیست به بخش جدید اضافه شود. تا پایان آزمون، حالت `staging` و فهرست گیرندهٔ مجاز را حفظ کنید؛ در این حالت درخواست دیگر شماره‌ها ارسال نمی‌شود.

در سایت «ورود با کد یک‌بارمصرف» را باز کنید، شماره آزمایش را وارد کنید، دریافت واقعی پیامک و ورود با کد را بررسی کنید. متن پاسخ ناشناختهٔ سرویس به معنی تحویل موفق اعلام نمی‌شود؛ رسیدن کد و مصرف آن در سرور آزمون اصلی است. درخواست مبهم خودکار تکرار نمی‌شود. اگر پیامک نرسید، از پشتیبانی TSMS فعال‌بودن URL API و دسترسی HTTPS خط خریداری‌شده و قالب پاسخ سرویس را بپرسید؛ رمز یا پاسخ خام سرویس را عمومی نکنید. برای برگشت، `enabled` را `false` بگذارید.

فقط پس از آزمون موفق ارسال و تأیید خط، برای استفادهٔ عمومی `environment` را `production` بگذارید. این کار رزرو عمومی یا ضبط را فعال نمی‌کند.

## ۲. ورود گوگل

در Google Cloud Console، OAuth Client از نوع Web application بسازید. صفحهٔ رضایت را تکمیل کنید و در حالت Testing، حساب آزمایش را به Test users اضافه کنید. در Authorized redirect URIs دقیقاً این مقدار را ثبت کنید:

```text
https://morshedapp.ir/index.php?r=%2Fauth%2Fgoogle%2Fcallback
```

سپس در بخش موجود فایل خصوصی قرار دهید:

```php
'google' => [
    'enabled' => false,
    'live_verified' => false,
    'client_id' => 'YOUR_WEB_CLIENT_ID',
    'client_secret' => 'YOUR_CLIENT_SECRET',
    'redirect_uri' => 'https://morshedapp.ir/index.php?r=%2Fauth%2Fgoogle%2Fcallback',
],
```

برای آزمون کنترل‌شده، دو پرچم `enabled` و `live_verified` را موقتاً `true` کنید، با حساب آزمایش از دکمهٔ گوگل وارد شوید و بازگشت موفق به سایت را بررسی کنید. این پرچم تنظیم دستی است و به‌تنهایی گواه آزمون موفق نیست. اگر آزمون ناموفق بود هر دو را `false` کنید. توکن هویت، امضا، صادرکننده، مخاطب، زمان، nonce، state و PKCE در سرور بررسی می‌شوند. ثبت‌نام گوگل شماره همراه را تأیید نمی‌کند.

## ۳. برنامک ایتا

در تنظیمات برنامک ثبت‌شدهٔ `morshed_app` در ایتایار، نشانی آغاز را `https://morshedapp.ir/` قرار دهید؛ نشانی ورود یا ثبت‌نام نباشد. لینک عمومی برنامک `https://eitaa.com/morshed_app` است. توکن برنامه باید مربوط به همین برنامک باشد، نه لینک عمومی یا نام کاربری آن.

```php
'eitaa' => [
    'enabled' => false,
    'live_verified' => false,
    'app_token' => 'YOUR_MINI_APP_TOKEN',
],
```

برای آزمون کنترل‌شده، دو پرچم را موقتاً `true` کنید و برنامک را از داخل ایتا باز کنید. مرورگر معمولی دادهٔ ورود بومی ایتا ندارد. ویترین باید بدون ورود و بدون درخواست شماره باز شود. دادهٔ آغاز فقط در سرور تأیید و کوتاه‌مدت در نشست نگهداری می‌شود؛ تا کلیک صریح ورود، حساب یا نشست ورود ساخته نمی‌شود. اطلاعات امضاشده و پاسخ رسمی بررسی اصالت، قبل از ایجاد ورود بررسی می‌شوند. فرم تکمیل نام کاربری و رمز پس از ثبت‌نام نمایش داده می‌شود.

دکمهٔ «اشتراک و تأیید شماره با ایتا» در حساب کاربری فقط با انتخاب کاربر پنجرهٔ اشتراک شماره را باز می‌کند. نتیجهٔ ظاهری callback یا `initDataUnsafe` اثبات شماره نیست. امضا، زمان، شناسهٔ ایتای متصل به همین حساب و مصرف‌نشدن تأیید در سرور بررسی می‌شوند؛ قالب ناشناخته رد می‌شود و راه پیامکی باقی می‌ماند. این مسیر باید با نسخهٔ واقعی ایتا و دادهٔ تماس واقعی آزمایش شود؛ آزمون‌های خودکار، سرویس واقعی ایتا نیستند. در صورت شکست، پرچم‌ها را خاموش کنید.

## ۴. تکمیل حساب و اطلاعات فوتر

بعد از ثبت‌نام، نام کاربری و رمز همان حساب تنظیم می‌شوند. نام کاربری ۴ تا ۳۲ حرف انگلیسی، عدد یا زیرخط است و با حرف شروع می‌شود. ورود با آن یا شمارهٔ تأییدشده و رمز ممکن است. تنظیم رمز برای حساب گوگل یا ایتا به معنی تأیید شماره نیست؛ برای مشاوره شمارهٔ تأییدشده لازم می‌ماند. رزرو عمومی طبق درخواست مالک همچنان بسته است.

در مدیریت، «تنظیمات عمومی» محل ویرایش جملهٔ فوتر، تماس، ایمیل، آدرس، لینک لوگو و لینک تأیید اینماد است. تصویر لوگوی فوتر و تصویر نماد را از همان صفحه بارگذاری کنید. تصاویر فقط PNG/JPEG تا ۵ مگابایت هستند. لینک‌ها باید داخلی یا HTTPS باشند؛ HTML یا اسکریپت نماد در فرم پذیرفته نمی‌شود. تا دریافت نماد رسمی، جایگاه اینماد خالی است و نشانی خالی نمایش داده نمی‌شود.
